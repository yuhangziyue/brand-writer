# 评估方法（交付物 D8 · 方法部分）

> 实现：`src/ragwriter/eval/{metrics,judge,evaluate}.py` · 评审提示词：`prompts/eval_judge.md` · 测试：`tests/test_eval.py`
> 口径来源：需求文档 06-quality-metrics（11 项指标与对照实验）、10-agent-architecture（意图与事件）、
> 2026-10-22 产品评审后的口径调整（boundary、拒答三分类、FAQ JSON-LD、拦截可见性）。
> 结果部分由 `ragwriter eval` 写进 [eval-report.md](eval-report.md) 的 `eval:results` 段，本文只讲方法。

## 1 · 评什么

每个用例是一段多轮对话（`eval/dialogues/*.yaml`），每轮有「输入（用户消息）→ 实际输出（CaseRun 的事件流与 done 载荷）→ 期望（expect）」。
评估器**按期望意图**逐轮打分，产出两项核心分数：

| 核心分数 | 回答的问题 |
|---|---|
| **原文匹配度**（faithfulness） | 输出说的每件事，品宣原文里有没有、写得对不对 |
| **扩写完整度**（completeness） | 该主题在原文里应有的要点写到了没有，体裁结构完整不完整，资料不足的地方处理对没有 |

核心分数是子项的算术平均，**只用于同一套用例下的横向比较**（如 E1 RAG vs 全文）。验收看子项：
06 号要求 100% 的项（数字一致、数字对象一致、陷阱题拒答）加上越界内容与拦截可见性，另列为**硬闸**，
任何一条不过就在报告首页标红 —— 它们不能被其他子项的高分平均掉。

## 2 · 为什么确定性为主、模型评审为辅

用模型给模型打分有 **generator-verifier gap**：评审模型与生成模型能力相当时，生成者犯的错评审者多半也发现不了。
本题最危险的错恰恰是「看起来很顺」的那种 —— 「AI 驱动流量增长 15 倍」，数字是真的、句子是通的，只是挂错了对象。
让同级别的模型判它，大概率判「支持」。

所以：

1. **凡是规则写得出来的，全部程序判定**：引用编号合法性、数字是否出现在所引片段、数字是否挂对标签（V3 区分词）、
   拉丁专名回查、禁用串、image_only 事实被引用、体裁结构、拒答字段、事件顺序。
   数字与专名的抽取和回查**直接调用线上校验 `ragwriter.verify.checks`**，不另写一套 ——
   线上与离线口径一旦不同，「评估 100%」就证明不了「线上闸在工作」。
2. **模型只评程序判不了的三件事**：句子与片段的语义支持度（ALCE 引用召回 / 精确）、要点是否被覆盖（仅确定性判不了的那部分）、
   扩写质量（论证是否把多页事实连起来）。
3. **评审模型尽量与生成模型不同**：`EVAL_JUDGE_MODEL` > `LLM_JUDGE_MODEL` > `LLM_MODEL`。
   落到与生成模型相同时，报告页眉标注「⚠️ 同模型评审，可信度降级」。
   `EVAL_JUDGE_MODEL` 与线上 V5 用的 `LLM_JUDGE_MODEL` 分开配，才能做到「生成 A、线上自检 A′、离线打分 B」。
4. **每条模型判定必须给依据原文，并且程序回查**：`evidence[].quote` 必须逐字出现在它声称的片段（或输出）里。
   查不到 = 评审在编依据，这条判定作废（不计分，单独计数「依据不实」）。判「支持 / 覆盖」却不给依据，同样作废。
   扩写质量里评审列出的「片段外新事实」也要能在输出里逐字找到；出现任何一条，分数程序兜底封顶 2/5。
5. 结构化输出走 `json_schema` strict，判定只能是枚举档位（支持 / 部分支持 / 不支持 等），不给自由打分的空间。
6. **`judge=None` 时模型项一律标「未评」，不记 0 分**：0 分会把「没评」伪装成「评了很差」。未评项不进核心分数均值。
7. 评审提示词与线上 V5 的 `prompts/judge.md` 分开：调线上 prompt 不应悄悄改变评估口径。报告记录评审 prompt 哈希。

人工抽检仍是最终裁判（06 号第 5 节）：报告末尾自动生成写作类前 3 篇的抽检表（句子、引用页、原文片段、确定性判定、模型判定、留空的人工判定列），
子曰填一遍，同时用来校准模型判别。

## 3 · 指标定义

### 3.1 原文匹配度（write / qa / revise）

| 指标 | 计算方式 | 性质 | 对应 06 号 |
|---|---|---|---|
| 引用覆盖率 | 事实句中带**合法**引用编号（编号都在本轮映射表里）的比例，成稿口径 | 确定性 | 引用格式遵从率（成稿） |
| 引用格式遵从率·改写前 | 同上，但统计对象是 `delta` 事件拼回的草稿（改写之前） | 确定性 | **引用格式遵从率**（06 要求改写前统计） |
| 引用支持率·确定性 | 带引用的事实句中，句内数字与拉丁专名都出现在所引片段的比例（= 线上 V2） | 确定性 | 引用召回的确定性下界 |
| 引用召回·模型 | 事实句中被所引片段**整体支持**的比例；无引用的事实句计为不支持；依据不实的判定从分母剔除 | 模型 | **引用召回**（ALCE） |
| 引用精确·模型 | 判为支持 / 部分支持的句子里，被评审列为依据（且依据回查通过）的引用 / 全部引用 | 模型 | **引用精确**（ALCE 的近似） |
| 数字一致率 | 逐个数字：出现在本句所引片段原文（含配对标签、出处口径）的比例；无引用的数字、引错片段的数字都算不一致 | 确定性 | **数字一致率**（V2） |
| 数字对象一致率 | 所引页上的配对数值中，挂对标签的比例（= 线上 V3：本数字区分词在场、兄弟区分词不在场） | 确定性 | **数字对象一致率**（V3） |
| 越界内容 | 命中 `forbidden_strings`，或正文引用了 `image_only` / `unverified` 事实（状态缺失时回语料查）⇒ 0 | 确定性 | 产品原则「截图客户名不使用」 |
| 期望数字命中 | `expect.numbers` 的 `{value, object}`：数字出现且同句含其对象词 | 确定性 | 数字对象一致率的正向用例 |
| 参考要素匹配（qa） | 参考答案中的数字、拉丁专名与 `expect.numbers` 逐项比对 | 确定性 | — |
| 字符级 F1（qa） | **仅供参考，不进任何分数** | 确定性 | — |

**为什么 qa 不用 BLEU / ROUGE**：中文短答里「8 倍」「增长了 8 倍」「8 倍增长」n-gram 重合度差很多但事实一样；
反过来把「8 倍」写成「15 倍」，n-gram 几乎不变而事实全错。测试 `test_qa_reference_elements_not_bleu` 演示了错答的字符 F1 仍 > 0.8。

**事实句**：沿用线上 V4 的 `is_factual`（含数字 / 拉丁专名 / 断言动词），再加一条「带引用的句子一律算事实句」——
作者自己声明了它有出处，就该接受出处检查。设问句与资料不足声明不算。

### 3.2 扩写完整度（write / revise；qa 只算要点与资料不足）

| 指标 | 计算方式 | 性质 |
|---|---|---|
| 要点覆盖率 | 每个 `expect.key_points`：**要点所在页被引用 且 关键词命中 ≥ 50% 且要点里的数字全部出现** ⇒ 覆盖；两者都不满足 ⇒ 未覆盖；只满足其一 ⇒ 不确定，交模型判（覆盖 1 / 部分 0.5 / 未覆盖 0）。无评审时不确定项从分母剔除并注明条数 | 确定性为主，模型补 |
| 体裁结构 | 见 3.3，满足项 / 检查项 | 确定性 |
| 资料不足处理 | 见 3.4 | 确定性 |
| 扩写质量·模型 | 评审按 1–5 档评「在不引入新事实的前提下，是否把多页事实连成论证」，必须列出跨页衔接句原文；归一化为 score/5 | 模型 |
| 跨页引用节占比 | 引用了 ≥2 个不同页的小节占比，扩写质量的确定性代理，**仅供参考** | 确定性 |

关键词用建库同一个 jieba 分词器与专名词典（`ragwriter.index.tokenize`），避免「LLM-原生GEO」被切碎。
数字是硬要求的理由：「AI 驱动流量增长 8 倍」与「订单增长 15 倍」共享一半关键词，只看比例会把前者误判成覆盖了后者。

### 3.3 体裁结构（来源 `prompts/planner.md` 与 2026-10-22 评审）

| 体裁 | 检查项 |
|---|---|
| blog | 有 `#` 标题 · 有导语 · **导语结论先行**（首句不以「随着 / 在…时代 / 近年来 / 如今…」铺垫开头、不是设问）· 正文 3–5 个二级小节 · 有结尾（末节标题含「结语 / 总结…」或末段以「因此 / 总之…」收束） |
| faq | Q/A 5–8 组 · 每问有答 · **答案首句直接回答**（不以铺垫开头，且含问句核心名词）· **`done.data.jsonld` 是 schema.org `FAQPage`，Question 数与正文一致，每个 Question 有 `acceptedAnswer.text`** |
| brand_intro | 标题 · 导语 · 正文恰好 4 节 · 节目齐全且顺序为「是谁 → 做什么 → 凭什么 → 服务谁」 |
| product_intro | 标题 · 导语 · 正文 3–5 节 · 节目「产品是什么 → 核心能力 → 效果数据（→ 交付与服务，可选）」齐全且有序 |

brand_intro / product_intro 的节目清单优先读 `prompts/genres/<genre>.{yaml,yml,json,md}`（D 组在写）；读不到时用内置表（按 planner.md 推断），
结构检查的 detail 里写明来源。节匹配看「小节标题 + 该节首句」是否含节目关键词，因为 planner 允许标题润色。

### 3.4 资料不足处理（2026-10-22 口径）

| 意图 | 通过条件 | 失败分类 |
|---|---|---|
| write | 期望的不足主题出现在 `done.data.boundary[].topic`；正文**没有**编出与该主题相关的数字；正文**没有**出现「品宣资料未涉及」类字样 | `missing_boundary` / `fabricated` / `body_phrase` |
| qa | 正文明确写出「资料未涉及」类表述（整答就是一句拒答也算） | `fabricated`（相关事实句里编了内容）/ `skipped`（静默跳过） |

write 正文里即使没有期望主题也出现了不足字样，记入问题清单（应进 boundary）。

### 3.5 按意图的特有指标

| 意图 | 指标 |
|---|---|
| 全部 | 意图正确（期望 vs intent 事件）；`inherited_topic: true` 时「主题继承」（intent 事件 `inherited.topic` 非空）；`options.inject_fault` 时「拦截可见性」 |
| out_of_scope 及一切期望拒答的轮次 | 拒答正确（`refused` 或 `refusal_kind ∈ {out_of_scope, insufficient_all}`）· **拒答理由正确**（`refusal_kind` 与期望一致；`out_of_scope` 意图默认期望 `out_of_scope`，融资 / 营收 / 员工数 / 价格应为 `insufficient_all`）· 给出 nearest_pages（非空且页码存在）· 未泄露 forbidden · 未生成正文（无含数字的事实句） |
| clarify | 是否追问 · 给出建议 · 建议在资料覆盖内（每条建议的关键词 ≥60% 能在某一页的标题 + 文字层 + 事实里找到） |
| qa（有答案） | 未误拒 · 检索命中（retrieval 事件前 5 条命中含黄金页 = key_points 的页；事件里没有有序列表时退到命中并集并注明口径） |
| explain | 解释依据一致：解释里提到的「第 N 页」都是上文真引用过的页 |
| revise | 同 write 的原文匹配度与体裁结构 |

### 3.6 拦截可见性（报告首页）

`options.inject_fault`（如 `v3_swap`）的轮次：事件流里必须先出现 `verify` 事件且 `result=fail`、`failed` 含 `V3`，
**其后**有 `patch` 事件，且成稿重新跑 V3 无错配。三条全满足才算 1。
这不是质量分，是「校验闸真的在工作」的证据：闸不响，其他指标再好也说明不了不编造。

## 4 · 汇总到 06 号指标

| 06 号指标 | 来源 | 备注 |
|---|---|---|
| 检索命中率 | qa 有答案轮次的「检索命中」 | |
| 引用召回 / 引用精确 | write、qa、revise 轮次的模型项，微平均 | 无评审时「未评」 |
| 数字一致率 / 数字对象一致率 | 同上的确定性项，按数字个数微平均 | 硬闸 |
| 引用格式遵从率 | 改写前草稿；无 delta 时退用成稿并注明 | |
| 陷阱题拒答率 | 一切期望拒答的轮次 | 硬闸 |
| 误拒率 | 有答案 qa 被判资料不足的比例 | |
| 编造数 | **人工**；报告给出确定性候选句数（引用回查不过 + 无引用事实句） | |
| 单篇耗时 | write·blog 轮次最慢一篇（同时给均值） | |
| 单篇成本 | `done.usage.cost_cny` / `cost`；缺字段时标 n/a | |
| 拦截可见性（新增） | inject_fault 轮次 | 硬闸 |

对照实验 E1–E3：同一套用例跑两种配置，各自 `evaluate_suite`，用 `compare_reports({"RAG": a, "全文": b})` 并排输出。

## 5 · 运行

```bash
# 离线重评已录制的运行记录（推荐：评估与生成解耦，换评审模型不必重跑生成）
ragwriter eval --runs build/eval/runs.jsonl
# 现场跑编排器，并把 CaseRun 存下来
ragwriter eval --live --save-runs build/eval/runs.jsonl
# 只算确定性指标
ragwriter eval --runs build/eval/runs.jsonl --no-judge
# CI：硬闸未过返回 1
ragwriter eval --runs build/eval/runs.jsonl --strict
```

结果写入 `docs/eval-report.md` 的 `<!-- eval:results:start -->…<!-- eval:results:end -->` 段（其余内容保留），
完整结构化结果写入 `build/eval/eval-report.json`。

## 6 · 已知局限

- **事实句判定是规则近似**：没有数字、专名、断言动词也没带引用的论断句（如「GEO 正在改变品牌传播」）不进分母。人工抽检兜底。
- **V3 是句级判定**：同一句里有多个配对数字时共享 V3 结论；一句同时写「流量和订单分别增长 8 倍和 15 倍」会被判通过（两个区分词都在场）。
- **「导语结论先行」「答案首句直接回答」是确定性近似**：只能拦住铺垫式开头与答非所问，判断不了「结论是否是全文最重要的那个」。
- **引用精确是 ALCE 的近似**：ALCE 逐条去掉引用看支持是否下降，这里用「评审是否把该引用列为依据」代替，调用次数从 O(引用数) 降到 O(句数)。
- **关键词覆盖受分词影响**：专名词典之外的新术语可能被切碎，导致要点落入「不确定」交给模型。
