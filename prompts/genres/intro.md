# 体裁：品牌介绍 / 产品介绍（共用一份，只换节目清单）

> 加载方式同 `genres/blog.md`；`{{program}}` 由加载器按体裁换成 `## 节目：brand_intro` 或 `## 节目：product_intro` 段。
>
> 与 Blog、FAQ 的根本区别：**介绍类是固定节目的说明文**——节目和顺序事先定死，不论证、不设问，
> 每一节只回答节目单上的那一项。两种介绍的写法相同，差别只在节目单。

## 规划

固定节目：按下面的节目清单与顺序开节，一项一节，不增不减；
目录里明显找不到某一项的依据时，仍保留该节（检索阶段会再判一次），并把缺的内容写进 `insufficient`。

{{program}}

- `heading` 可以润色，但与节目的对应关系与顺序不变。
- `lede_points` 1–2 条（一句话说清这个品牌 / 产品是什么）；`ending_points` 1–2 条。

## 写作

介绍类文章的一节，只回答节目单上本节对应的那一项，不越界写其它项。

{{program}}

- 第三人称、正式、可信，说明文语气；不设问、不写口号。
- 120–250 字，1–2 段。
- 团队背景、荣誉、论文数、效果数据等表述必须与片段原文一致，不拔高（片段写「30+篇」就不能写「数十篇」）。
- 案例数据只能描述片段里的那个案例，不得泛化为「所有客户」「普遍提升」。

## 导语

导语 1–2 句：一句话说清这个品牌 / 产品是什么、为谁服务，事实只取各节已通过校验的句子（保留原编号）。

## 结尾

结尾 1–2 句：概括核心价值；最后一句可以是不含事实的合作邀请，不带引用。

## 节目：brand_intro

品牌介绍，四节，顺序固定：

1. **是谁**：品牌定位、愿景、团队背景。
2. **做什么**：核心业务、方法论与服务内容。
3. **凭什么**：技术体系、团队与方法上的依据、行业认可。
4. **服务谁**：服务对象、行业与案例。

## 节目：product_intro

产品介绍，四节，顺序固定（核心能力较多时可拆成两节，总数不超过五节）：

1. **产品是什么**：解决什么问题、定位。
2. **核心能力**：做什么、怎么做，讲清能力而不是形容词。
3. **效果数据**：案例与指标；每个数字写出它描述的对象与出处口径。检索用的 `sub_question` 要点明「效果」「数据」或「案例」。
4. **交付与服务方式**：怎么合作、怎么交付。
