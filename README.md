# brand-writer · 基于 RAG 的品牌内容写作系统

万悉科技笔试题二。输入一个主题，基于品宣 PDF 写出官网 **Blog / FAQ / 品牌介绍 / 产品介绍**：
每个事实句都标注来源页码，可以点开核对原文；资料里没有的内容不写，也不猜。

```bash
make install && make index      # 装依赖（含 bge-m3）并建索引库 build/index/rag.db
make demo                       # 打开 http://127.0.0.1:8000
```

- 没有 `LLM_API_KEY` 时，页面自动进入**回放模式**，播放 `build/fixtures/` 里录下的真实运行记录，页面顶部有琥珀色横幅标注。
- 有 key：复制 `.env.example` 为 `.env`，填 `LLM_API_KEY / LLM_BASE_URL / LLM_MODEL`（OpenAI 兼容协议，DeepSeek、Qwen、Claude 中转都可以）。
- 其它命令：`make test`（273 条单测，不需要 key）· `make eval`（真链路评估）· `make samples`（重新生成示例）。

## 流程

题二的流程是：读取 PDF → 解析与切分 → 建立检索索引 → 输入主题 → 检索资料 → 构建上下文 → 生成内容 → 展示引用依据。
系统在「输入主题」和「检索资料」之间加了一步**主题审核与确认**：

```mermaid
flowchart LR
  A[写作台指定体裁<br/>或对话里说一句话] --> B[① 主题审核<br/>模型：有效吗？精确主题？<br/>中心观点或选品？要点？资料缺口？]
  B --> C[② 与用户确认<br/>确认卡：确认 / 改主题 / 选备选]
  C --> D[③ 检索<br/>每节多路查询 + 混合检索]
  D --> E[④ 构建上下文<br/>回填整页、编号]
  E --> F[⑤ 生成<br/>逐节写作 → 导语和结尾 → 通篇润色]
  F --> G[⑥ 引用与校验<br/>V1–V5 逐句校验，不过的改写或删除]
  G --> H[成稿 + 引用依据 + 校验报告 + 资料边界]
```

**Agent 的形态：受控工作流，而不是自主工具调用。**流程骨架由程序按上图依次调用；每一步的**判断**都交给模型、按提示词来做：
意图、体裁、主题是否有效、中心观点、选哪个产品、每节写什么、这句话有没有被片段支持。
不让模型自己决定要不要检索，是因为模型可以选择不检索、直接用自己的记忆回答，这违反「口径只来自品宣资料」。

对话入口除了写作，还能识别这几类请求：
- **问答**：按回答形状裁剪，问数字只给数字，核实一个说法就先说对或不对；
- **改写上一篇**：缩短、扩写、换语气、重写、删节、加一节、改标题；只改目标块，引用编号保持不变；
- **闲聊**、**越界请求**。

## PDF 解析与 Chunk 策略

详见 [corpus-report.md](docs/corpus-report.md)、[structured-content.md](docs/structured-content.md)。

- **三路解析，交叉校验**：
  - PyMuPDF 文字层是唯一的事实源，**按内容流的块序读取**，不按版面排序（`sort=True` 会把多栏页的数字和标签拆散，块序里 30 组配对全部紧邻）；
  - LLM 把每页结构化成页卡：要点、数字与标签的配对；页卡里的每个数字和标签都必须能在文字层找到；
  - 整页视觉复核补上文字层拿不到的**图示关系**，比如第 5 页 GEO 三阶段各自的注入点。
- **事实分四级**：`verified` 350 条（文字层逐字可核）· `image_structural` 58 条（关系来自图示，引用时写「据第 N 页图示」）· `image_only` 17 条（截图里的数字和客户名，默认不用）· `unverified` 1 条。
- **父子两级**：父 = 一页（引用单位），子 = 一条要点、一个数字配对或一个页标题（检索单位）。每个子块带确定性前缀「第 N 页 · 章节 · 页标题」，由程序拼出，不调模型。
  页标题本身也入库成可引用的事实：第 2 页的愿景「让好的品牌进入 AI 的深度记忆」只出现在页标题里。

## 索引与检索

- **存储**：SQLite 单文件 `rag.db`，FTS5 做 BM25（jieba 预分词，品牌别名「万悉 / 万悉科技 / Trendee」在分词层归一），bge-m3 的 1024 维向量以 BLOB 存在同一个库里，查询时整块点积。约 430 条事实，不需要向量数据库服务。
- **每节多路查询**：规划给出检索问句；问答时意图模型另给 1–3 条带别名和原文说法的改写。两路召回后用 RRF（k=60）融合，每路查询的单路第一名保底进入上下文。
- **充分性**：写作按节判断：稠密 top1 余弦 τ=0.604，由标定集的 10 道可答题和 8 道陷阱题得出，余量只有 0.01。问答**不在生成前按检索分数拒答**，而是交给读过片段的作答模型判断；它说「未涉及」就算拒答。检索相似度衡量的是「话题相关」，不是「能不能答」。
- **体裁差异**：
  - 产品介绍只检索选中产品的资料（按事实粒度圈定），不让别的产品的功能被写成本产品的；
  - 介绍类会优先取规划给出的预计页码上的事实。

## 上下文构建

- 命中的子块回填所在整页，按页分组；每组前加一行「第 N 页《页标题》」，最相关的放在首尾。
- 每个片段编号 `[S4 | 第9页]`，图示类片段标「· 图示」，数字配对附出处口径。
- 只放 `verified` 和 `image_structural` 两级。
- **同一事实只在一节里用**：前面小节已经引用过的事实（按内容判断，不只按编号），不再给后面的小节。
- **为什么全文只有约 6300 token 还要做 RAG**：显式选出的片段才能把引用落到页，并由程序逐句校验；少放无关内容，模型顺手编造的机会也更少；真实场景下一个品牌会有几十上百份资料。

## 体裁与 Prompt

| 体裁 | 结构 |
|---|---|
| Blog | 规划先定**中心论点**，3–4 节组成论证链（现象 → 问题 → 解法 → 证据）；每节标题是分论点判断句，写明本节作用和如何承接上一节；导语亮出论点 |
| FAQ | 5–8 组问答对，没有导语和结尾；答案第一句直接回答；附 schema.org `FAQPage` JSON-LD |
| 品牌介绍 | 市场通行结构：概述 → 使命愿景 → 核心业务 → 核心优势 → 团队 → 荣誉认可 → 服务行业与案例 → 联系方式；资料里没有的节目不写 |
| 产品介绍 | 先**选品**，再按：定位 → 解决的问题与适用对象 → 核心功能 → 工作原理 → 效果与案例 → 合作与交付 |

## 幻觉控制与引用溯源

| 闸 | 检查 | 性质 |
|---|---|---|
| V1 | 句中引用编号都在本次映射表里 | 确定性 |
| V2 | 数字、百分比、年份、拉丁专名、范围口径词（「海外」「越来越多」）都出现在所引原文里；引用案例页时须点明是哪个案例 | 确定性 |
| V3 | 数字挂对对象（「15 倍」属于订单增长，不是流量增长）；同一句不混用同页两个统计口径 | 确定性 |
| V4 | 事实句必须带引用；导语句一律要引用 | 确定性 |
| V5 简版 | 句子与所引片段的字面支持度 ≥ 0.15，拦下为过校验硬挂的引用 | 确定性 |
| V5 | 模型判别：主体错位、以个体代整体、片段里没有的判断 | 模型 |

- 不过的句子带着失败原因改写，最多两轮，仍不过就删除。改写和删除都会推送给前端：被拦下的句子用红色删除线显示，并用人话写明原因。演示开关可以人为注入一处数字错配，现场展示 V3 拦截。
- **资料不足**：
  - 写作前，确认卡告诉用户哪些内容资料里没有、文中不会写；
  - 写作类成稿里不出现「品宣资料未涉及」，缺口列在文末的「资料边界」；
  - 问答类直接回答「品宣资料未涉及 X」；
  - 越界请求（写代码、问天气）和资料不足（融资、营收、竞品对比）分开处理。
- **引用溯源**：每个 `[S编号]` 映射到 fact_id 和页码。前端角标显示「p9」，图示类显示「p5·图」；点开能看到原文片段、页面缩略图和对应文本块的高亮框。

## 评估

方法见 [eval-method.md](docs/eval-method.md)，结果见 [eval-report.md](docs/eval-report.md)。19 条多轮对话用例（覆盖全部意图和四种体裁）在真实模型上跑：

2026-10-24 最终版（生成模型 deepseek-v4-pro，19 条用例 37 轮）：

| 指标 | 结果 | 目标 | 说明 |
|---|---|---|---|
| 数字一致率 | ✅ 1.00（105/105） | 100% | 硬闸：成稿里每个数字都能在所引原文里找到 |
| 数字对象一致率 | ✅ 1.00（69/69） | 100% | 硬闸：数字挂对了对象（15 倍是订单，不是流量） |
| 陷阱题拒答率 | ✅ 1.00 | 100% | 硬闸：越界请求与资料里没有的问题都拒答 |
| 拦截可见性 | ✅ 1.00 | 100% | 硬闸：注入的数字错配被 V3 拦下，前端看得到删除和原因 |
| 误拒率 | ✅ 0.00 | ≤ 10% | 资料里有答案的问题没有被拒 |
| 检索命中率 | ✅ 0.90 | ≥ 80% | 问答类前 5 条命中包含标准答案所在页 |
| 引用格式遵从率 | ❌ 0.92 | ≥ 95% | 统计的是校验**之前**的草稿；没带引用的事实句由校验改写或删除，不会进成稿 |
| 单篇耗时 | ❌ 95 秒（均值 75 秒） | ≤ 90 秒 | 最慢一篇是 Blog，主要耗在逐句校验和改写的多次模型调用 |
| 原文匹配度 / 扩写完整度 | 写作 0.94 / 0.82，问答 0.92 / 1.00 | — | 子项均值，只用于横向比较 |

本次评估没有启用模型评审（引用召回、引用精确、扩写质量记为「未评」，不是 0 分），配置 `EVAL_JUDGE_MODEL` 后可以补上。

确定性指标为主，模型评审为辅：生成模型和评审模型能力相当时，评审往往发现不了生成者的错，所以能由程序判定的都由程序判定。

## 模型选择

- 生成、判别、主题审核都用 DeepSeek V4 Pro（开发期经本机 OpenAI 兼容中转）：国内可达、成本低、中文写作质量够用。全程关闭思考模式：逐句判别调用频繁，思考 token 既占预算又拖延迟。
- 适配层只认 OpenAI 兼容协议，不绑任何厂商 SDK；换模型只改 `LLM_BASE_URL` 和 `LLM_MODEL`。
- 嵌入用本地 bge-m3：中英混排，无网络也能检索。

## 已知局限与下一步

1. **品牌介绍跑出来不稳定**：8 项节目共用第 2、3、13 页这同一批资料，按节分别检索时会串节或漏节，比如「使命与愿景」里写进了团队，「联系方式」时有时无。
   下一步：品牌介绍改成一次取全相关页，再由模型把事实分配到各个节目。
2. **源数据有两处缺主语**：
   - 第 2 页「发表论文 30+ 篇」这类数字配对的标签没有主语，会被写成「团队发表」；
   - 第 9 页两张榜单（全球网站月访问量 / 国内 App 月活）的标签没带榜单名，目前靠 V3 的「同句同口径」兜底。
   下一步：页卡解析时把主语和组标题补进标签。
3. **V5 判别和生成是同一个模型**，存在「自己审自己」的盲区：最终几轮示例里，V5 判别调用了 125 次，一次都没拦下，而人工审查仍发现了问题。配 `LLM_JUDGE_MODEL` 换成另一个模型即可。
   最典型的漏网是**以偏概全**：第 30 页列了 10 个服务行业，成稿写成「主要服务精细化工与金融服务」。每个专名都有出处，确定性校验拦不住，只能靠独立的判别模型或人工审查。
4. **资料薄的产品写出来很短**：「GEO 监控系统」在品宣里只有第 27、28 页，产品介绍只写得出一两节。主题审核只看得到页标题，判断不了资料够不够写，这一点还做不到。
5. **充分性阈值脆弱**：τ 和陷阱题之间只差 0.01，换了语料或模型要重跑 `ragwriter calibrate`。
6. **改写**：「改短一点」压缩力度不够（实测 −28%）；改标题偏弱；改写之后不做通篇润色，以免抵消用户刚提的要求。
7. **单篇耗时**：Blog 加上主题审核、V5 判别和润色，大约 60–100 秒。
8. **没做的对照实验**：「全文直接放进上下文」与 RAG 的对照实验（回答「语料只有 6300 token 为什么还做 RAG」最有说服力的证据），本次没有实现。
